# Agent backend testing

This note documents how the stable llmtk agent backend is made testable through
`uv`, the CLI, and MCP, plus the gaps that remain.

## Scope

The "stable" surface under test is the set of supported commands only:
`doctor`, `context export`, `preflight`, `analyze`, `stderr-thin`, `test`,
`deps`, `capabilities`, and `agent mcp`. Planned commands (`bench`, `reduce`,
`tidy`, `format`, `gate`, `diff-context`, `lsp-bridge`) are intentionally *not*
advertised as stable capabilities and are not exercised here.

## What was added

- **`uv.lock`** — generated by `uv sync` and committed. `uv` remains a
  dev/build tool only; runtime dependencies are still empty and pipx installs
  the `llmtk_bootstrap` wheel unchanged.
- **`tests/fixtures/cmake_min/`** — a minimal, buildable CMake project: one
  `hello` executable target plus two CTest cases registered with
  `cmake -E true` / `cmake -E false` (deterministic pass/fail with no build
  step). `src/main.cpp` doubles as the known-good preflight input.
- **`tests/test_integration.py`** — integration tests that exercise:
  - `context export` on the fixture (compile_commands + CMake File API replies);
  - `preflight` on a known-good file (exit 0) and a known-bad file (exit 3);
  - `test --json` on a passing and a failing CTest case;
  - `deps` on the fixture build directory (codemodel + `hello` target);
  - MCP `initialize`, `tools/list`, and `tools/call` for
    `capabilities` / `preflight` / `diagnostics`.

  Each test runs inside a throwaway copy of the fixture with the toolkit's
  project-root/exports globals repointed at it, so the repository tree is never
  mutated. Tests that need a real CMake configure are guarded by
  `@skipUnless(cmake + ninja + C++ compiler)` so the suite still runs on
  minimal CI. Per the project preference, configuration prefers Homebrew
  clang 20 (`/opt/homebrew/opt/llvm@20`) when present and falls back to the
  platform default compiler otherwise.

- **CI (`.github/workflows/ci.yml`)** — a new `tests` job installs uv +
  cmake/ninja/g++ and runs `uv run --locked python -m unittest discover -v`,
  turning the stable-surface contract into enforced behavior.

## Implementation fix discovered by the tests

`agent` MCP/JSON `tools/call llmtk.preflight` previously mapped *any* non-zero
preflight exit code to a JSON-RPC error, collapsing the structured findings to
the string `"preflight failed with exit code 3"`. But preflight exit codes 2
(warnings) and 3 (errors) mean "ran fine, found issues" — the normal, useful
outcome — analogous to `test` reporting failing tests.

Fix (in `llmtk/commands/agent.py`): `_artifact_response` now accepts
`success_exit_codes`, and `_handle_preflight` passes `{0, 2, 3}`, so findings
come back as a successful artifact response containing the full JSON. No public
command surface was added.

## Commands run

```
uv sync                                   # generates/refreshes uv.lock
uv sync --locked                          # verifies the lock is consistent
uv run python -m unittest discover        # 13 tests, OK
uv build --no-sources                     # builds sdist + wheel
```

## CLI-level coverage

`tests/test_cli_surface.py` drives commands through the real argument parser
(`create_parser` → `parse_args` → `func`) so registration and argument wiring
are covered too:

- `doctor` writes a structured `exports/doctor.json` (`_meta`, `_summary`,
  per-tool entries).
- `stderr-thin --log ... --json ...` produces structured diagnostics JSON.
- `context export --deep` summarizes targets/toolchains/cache on the fixture.
- `analyze --sarif src` produces real per-tool reports
  (`exports/reports/{clang-tidy,cppcheck,iwyu}.json`) plus `analysis.sarif`.

Adding the deep test surfaced and fixed a real bug: `_load_reply_json` looked up
File API replies by bare kind (`"codemodel"`), but stateless queries are keyed
by query name (`"codemodel-v2"`), so deep mode silently emitted empty
targets/toolchains/cache. It now matches by the entry's `kind`.

### `analyze` and tool availability

`llmtk analyze` runs clang-tidy, IWYU, and cppcheck against the compile database
and emits **real** parsed JSON — not placeholder/stub output. When a tool isn't
installed it writes an honest report instead of fabricating findings:

- `{"ok": false, "status": "missing_binary", "message": "..."}` (clang-tidy / cppcheck)
- `{"ok": false, "status": "missing_runner", ...}` (IWYU)
- `{"ok": false, "status": "missing_compile_commands", ...}` when there is no
  compile database, and `"no_translation_units"` when the filters match nothing.

The CLI test asserts that every report is either a real run (with `command` /
`diagnostic_counts` / `duration_seconds`) or one of those honest "not run"
statuses with no `diagnostics`/`issues`. It exercises the real clang-tidy path
when clang-tidy is on `PATH` (e.g. the project's clang 20), and the
missing-tool path otherwise, so it passes on minimal CI without the analyzers.

## Remaining gaps

- Preflight integration tests run with `--no-syntax` for determinism, so the
  external clang syntax-probe path is not covered.
- `agent mcp` is tested at the message-handler level (`_handle_message`); the
  stdio read loop (`MCPServer.run`) is not driven end to end.
